# Shuffle+ v7.3.1 — Démarrage et connexion sécurisés

## Pourquoi cette version

Sur certaines installations, un cache de navigateur ou un ancien Service Worker pouvait laisser Shuffle+ sur l’écran de connexion avec un bouton Spotify inactif. La suppression complète des données du site rétablissait le fonctionnement, mais supprimait inutilement la session locale.

La v7.3.1 ajoute une récupération ciblée qui conserve les données utiles.

## Nouveautés

### Secours disponible même si `app.js` ne démarre pas

La page charge désormais `startup-recovery-7.3.1.js` avant le module principal. Cette petite couche indépendante reste utilisable si le fichier principal est absent, obsolète ou en erreur.

Le lien **Connexion bloquée ?** propose deux opérations :

- **Réparer Shuffle+** : supprime uniquement les caches Shuffle+ et désenregistre le Service Worker, puis recharge la page. La session Spotify, les mix, les réglages et l’iPhone préféré sont conservés.
- **Réinitialiser la connexion Spotify** : supprime uniquement les jetons et l’état OAuth Spotify, puis répare le cache. Les autres données Shuffle+ sont conservées.

### Réparation automatique limitée

La couche de secours attend le signal de démarrage envoyé par `app.js`.

- si ce signal n’arrive pas dans les dix secondes ;
- si un script ne peut pas être chargé ;
- ou si la version chargée ne correspond pas à la page ;

Shuffle+ tente une réparation automatique du cache une seule fois. Une protection en `sessionStorage` évite les boucles de rechargement.

### Session Spotify plus robuste

- l’état PKCE est maintenant horodaté ;
- les tentatives incomplètes ou expirées sont nettoyées hors retour OAuth ;
- un access token associé à une date d’expiration corrompue est supprimé sans effacer un refresh token encore utilisable ;
- les accès à `localStorage` et `sessionStorage` tolèrent les erreurs du navigateur ;
- un message explicite apparaît lorsque le navigateur empêche l’enregistrement du code PKCE ;
- les données temporaires sont nettoyées après un échange de token refusé.

### Cache PWA moins susceptible de charger un ancien script

Le Service Worker utilise désormais une stratégie **réseau d’abord** pour les scripts, feuilles de style et manifeste. Les paramètres de version sont respectés en priorité et les requêtes réseau évitent le cache HTTP.

Le cache hors connexion reste disponible comme solution de secours.

## Données conservées

Une réparation normale ne supprime pas :

- les playlists et la bibliothèque locale ;
- les mix et profils ;
- les scènes et réglages Adaptive DJ ;
- l’iPhone Spotify préféré ;
- les réglages d’interface ;
- les statistiques et objectifs ;
- les paramètres du serveur de synchronisation ;
- la session Spotify, sauf choix explicite de sa réinitialisation.

## Tests ajoutés

La v7.3.1 teste notamment :

- la réparation d’un état PKCE partiel ;
- la conservation du refresh token après une expiration locale corrompue ;
- la conservation des préférences lors d’une réinitialisation Spotify ;
- le fonctionnement avec un stockage navigateur indisponible ;
- l’ordre de chargement de la couche de secours ;
- les signaux de démarrage et d’erreur ;
- la stratégie réseau prioritaire du Service Worker.
