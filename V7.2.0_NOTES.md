# Shuffle+ v7.2.0 — Architecture, navigation et performances

Date : 30 juillet 2026

## Objectif

Commencer le découpage du cœur de Shuffle+ et réduire le travail de rendu sur mobile, sans modifier les données utilisateur, les URL iOS, le moteur de mélange ou l’authentification Spotify de la v7.1.1.

## Nouveautés techniques

- Nouveau module `core/app-menu.js` : liste des rubriques, groupes de navigation, normalisation des URL, stockage du menu actif et positions de défilement.
- Nouveau module `core/html-utils.js` : échappement HTML partagé.
- Une seule rubrique standard est construite à la fois ; les treize autres écrans ne sont plus rendus en arrière-plan.
- Le mode Conduite conserve son rendu autonome et ses minuteries spécifiques.
- Le build copie maintenant les modules imbriqués du dossier `core/`.
- Vérification automatique du graphe des imports relatifs depuis `app.js`.
- Vérification de l’artefact `dist/` après le build.
- Cache PWA d’exécution limité à 120 entrées.
- Installation du nouveau Service Worker uniquement lorsque tous les fichiers essentiels sont disponibles.
- Les icônes facultatives n’empêchent pas une mise à jour si l’une d’elles est momentanément indisponible.
- GitHub Actions valide également les Pull Requests sans déployer leur contenu.
- Workflow actualisé avec `actions/checkout@v7` et `actions/setup-node@v7`.

## Compatibilité

- Aucune migration des préférences ou des sauvegardes.
- Les clés `localStorage`, IndexedDB et la synchronisation serveur restent compatibles avec la v7.1.1.
- Les Redirect URIs Spotify restent inchangées.
- Le déploiement reste statique sur GitHub Pages.

## Tests ajoutés

- échappement HTML partagé ;
- unicité et cohérence des rubriques ;
- validation des vues URL ;
- stockage indisponible ;
- nettoyage des positions de défilement ;
- présence des branches de rendu différé ;
- préchargement des modules par le Service Worker ;
- limitation du cache d’exécution ;
- validation du graphe des imports ;
- validation du contenu de `dist/` ;
- démarrage réel du serveur local et contrôle HTTP des ressources essentielles.
